# Huddle 免費／Pro 與推薦方案草案

2026-09-21。價格已確認：NT$149／月、NT$1,290／年。下列功能額度與推薦受益對象是提案，尚未套用、公布或收費；推薦人／新朋友／雙方受益仍待使用者回答。不得把此草案當成正式條款。

## 定位與功能區分

免費版讓個人完整整理生活，Pro 讓多人協作更方便。不要鎖住新增任務、拖曳排程、基本專注與已建立的資料。年費相較月繳全年 NT$1,788 少 NT$498（約 28%），年繳一次收 NT$1,290，月均 NT$107.50 只能作輔助顯示。

| 任務、日／週／月日曆、拖曳排程、重複任務 | 完整使用 | 完整使用 | 既有功能，無付費限制 |

建議第一版 Pro 聚焦「更多共享夥伴＋多人約交集」，容量額度完成後再加入可售項目。沒有完成的功能不得用現在式列在購買頁。不要把 Google 登入描述為 Google Calendar 同步；目前沒有該整合。Google Calendar 同步已由使用者提出需求，單／雙向待確認，詳見 `../integrations/google-calendar-sync.md`；完成前不列已提供。版本歷史、團隊管理等另列未定路線圖，不用來支撐首發售價。

舊用戶：沿用既有免費權益，不追溯回收；正式啟用前建立 legacy 權益快照，新增付費功能才依方案判斷。新註冊帳號採公告後的規則。到期後不刪資料；閱讀、匯出、刪除保留；超額時限制新增而非封鎖整個帳號。既有共享不要突然撤銷，可保留現況直到主動移除，新增時檢查額度。主辦以成功建立的唯一 invitation 計數，重試不重扣，取消不返還以免刷寄信；回覆與重寄不另扣。每月額度按 Asia/Taipei 曆月重置，UI 顯示日期。

## 推薦活動建議

建議命名「揪朋友，一起 Huddle」。每個已驗證帳號有不含個資的隨機推薦碼，例如 HUD-7K3P9Q；分享連結使用正式網域的 /r/<code>，複製連結／系統分享由本人點擊，不自動寄信或讀取聯絡人。

建議雙方各得 3 個月 Pro，受益對象待確認。3 個月按實際日曆月計，不暗中改成 90 天；商店提供的期間若不同，必須依實際設定改文案並再次核定。推薦活動與一般免費試用不可重複疊加同一期間。建議作首發 90 天活動（活動日期另定），每位推薦人最多獎勵 4 位有效新朋友／共 12 個月；不先承諾永久無限送。

新朋友應是活動開始後新註冊帳號，註冊 14 天內可輸入一次；Google／Apple 已驗證身分或 Email 驗證完成後才成立。禁止自推與互推、重複兌換；僅輸入錯誤碼不消耗次數。已經是使用者的人可以推薦新朋友，但不能再作為新朋友重領。建議不要求購買、不要求完成任務才成立，符合「朋友輸入就送」；商店仍可能要求確認免費優惠。遇風險待審，不把 IP 相同直接視為作弊，以免誤傷家庭與公司。

## 介面流程

1. 設定 → 邀請朋友：我的推薦碼、複製／分享、輸入朋友推薦碼、已獲得／待領取獎勵、期限和條款。手機放帳號設定中；官網導頁同時提供中英文。
2. 新朋友輸入 → 檢查帳號／活動 → 顯示推薦人自選顯示名稱、獎勵期間與兌換條件 → 明確確認。不能顯示推薦人的 Email。
3. 完成推薦關係綁定 → 狀態為「獎勵待領取」；進行官方優惠兌換 → 伺服器確認後才顯示「已啟用，至 YYYY/MM/DD」。不能因按下按鈕就顯示已加 3 個月。
4. 已有付費訂閱者：顯示商店確認的優惠生效日／下次付款日；年繳者獎勵不得在已付費年度內重疊消耗。不能只把 Huddle 到期日加長，Apple／Google 照常續扣。
5. 商店暫不支援或不符合資格：保留待領取獎勵與清楚原因，不靜默減少時長、不導引使用者繞過商店付款。每個平台的免費／月繳／年繳／已取消／到期情境驗證完成後，才向該群體開放活動。

分享文案草稿（以雙方受益核定為前提）：「來一起用 Huddle 整理生活！註冊後輸入我的推薦碼 {code}，符合活動條件並完成優惠兌換，我們都能獲得 3 個月 Pro。{link}」英文：“Bring your day together with Huddle. Sign up with my code {code}; once eligible and redeemed, we each get 3 months of Pro. {link}”

## 商店落地與不能混淆的地方

Apple 3.1.1 限制以自訂機制解鎖付費功能。推薦碼只作推薦關係歸因，獎勵使用官方 offer codes；這是實作建議，不是保證審核通過。送審備註應完整說明推薦條件与商店兌換，不隱藏活動。Apple offer 可分新／現有／到期訂閱者；目前官方亦提供免費 offer 不自動續訂的設定。選擇適合的新客免續扣方案，既有會員另驗證優惠生效排程。

Google Play 自訂 promo code 僅限未曾訂閱者；一次性碼與現有訂閱需不同處理。官方 promo trial 需付款方式且到期自動續訂，兌換前必須寫清楚首扣時間、金額和取消方式，不能跨平台一律聲稱「不用綁卡、不會自動扣款」。現有 Google 訂閱可評估官方 defer billing 延後續扣，不用本地時間戳冒充商店延期。

既有 RevenueCat webhook 只認 production recurring 權益；尚不能假定免續扣 offer 或額外推薦權益被正確同步。需擴充權威驗證／reconciliation，不能讓一般 webhook 覆寫掉獎勵，也不能把商店交易轉移後的同一奖励複製給兩個 Huddle 帳號。沒有原生優惠設定與實機驗證前，不上線「輸入立即開通」按钮。

## 後端設計邊界

建議新增 campaign、referral_codes、referrals、reward_grants、store_redemptions 五個領域。推薦碼唯一；referrals 對 invitee 建唯一約束；reward 對 referral+beneficiary+campaign 唯一；商店交易／兌換事件同樣去重。用伺服器 transaction 綁定推薦與保留獎勵，Webhook 重送不重發。狀態 accepted → reward_pending → issued → redeemed／failed／revoked，保留審計，不覆寫歷史。將「推薦資格成立」與「Pro 已生效」分開。

server 驗證 user ID、驗證時間、活動期限、名額、相同帳號、自推、已兌換；client 只能讀自己的碼與獎勵狀態，不能寫 pro expires_at。限流和風險暫停機制需可申訴，刪帳重註防重領須採最少資料及明確留存期限，不保存可公開查詢的 Email 雜湊名單。跨平台同帳號只領一份獎勵。

實作驗收：同時兌換同碼、重試、大小寫／空白、過期活動、4 次上限、自推、已驗證／未驗證、月繳／年繳、取消續訂／退款、換帳號／恢復購買、商店兌換失敗／中斷、跨平台、重複／亂序通知、到期降級與舊帳號權益。尚未建立 migration 或改變任何人的方案。

## 經濟與上架順序

3 個月牌價 NT$447，雙方合計 NT$894；這是名目優惠價值，不等於實際獲客成本。須另量測 Email／儲存實際成本、有效推薦率、兌換率、試用後 30／90 天付費轉換與續訂；先小規模活動再决定延長。年費折扣與推薦優惠的疊加需算入收入預估，不用假設全部會付費。

先核定功能額度與受益對象，再做後端權限／推薦 ledger，接商店官方優惠與實機沙盒，最後更新雙語定價頁／活動條款並送審。商店帳號、商品、稅務與收款、客服與隱私／退款頁等沿用 launch-checklist。此文檔不代表商店或正式寄信已配置。
