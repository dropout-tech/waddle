## 4. Restore behavior (Project settings > General)
Exact options [DOC] https://www.revenuecat.com/docs/projects/restore-behavior :
1. "Transfer to new App User ID" (DEFAULT)
2. "Transfer if there are no active subscriptions"
3. "Keep with original App User ID" ("Use with caution")
4. "Share between App User IDs (legacy)" (only existing legacy projects; cannot re-enable once left)
- Default behavior: same Apple ID, UserA bought, UserB logs in on same device and restores => UserB gets access, revoked from UserA (only one at a time).
- Option 2: transfers unless the purchase has an active subscription; designed for strict "sub belongs to one user" apps while letting churned users start fresh.
- Option 3: returns error RECEIPT_ALREADY_IN_USE for restore AND new purchase under a different ID; "only allowed for apps that require every customer to create an account before purchasing"; support must handle account recovery.
- Applies to purchases too (not just restore), except legacy. Applies only to purchases tied to an IDENTIFIED user ID; if tied to anonymous ID they are aliased/merged instead.
- Separate sandbox restore behavior toggle: "Use a different restore behavior for sandbox".
- Webhook: TRANSFER event (App Store supported), sent only to destination user, fields transferred_from[]/transferred_to[] [DOC] event-types page. Linking restore->TRANSFER is natural but page doesn't spell restore explicitly [INF].
- RC's guidance table: login-optional or purchase-before-account => Transfer to new App User ID (required); account-required => Transfer (recommended) ; account-required + strict one-user rule => Keep with original App User ID.
- Caveat [DOC]: if "Track new purchases from server-to-server notifications" is on, don't combine with options 2/3/4 unless appAccountToken matches RC App User ID (valid UUID v4) or isn't set.

## 5. Apple review / sandbox
- Apple TN2413 (archived, last updated 2018-05-01): "The App Review team reviews apps in the sandbox. Always verify your receipt first with the production URL; proceed to verify with the sandbox URL if you receive a 21007 status code." 21007 = sandbox receipt sent to production. https://developer.apple.com/library/archive/technotes/tn2413/_index.html . NOTE: refers to deprecated verifyReceipt; modern equivalent (App Store Server API environment field) not checked.
- Apple: TestFlight apps always run in sandbox https://developer.apple.com/documentation/storekit/testing-in-app-purchases-with-sandbox ; notifications carry environment property there.
- RC on review [DOC] https://www.revenuecat.com/docs/test-and-launch/app-store-rejections : reviewer's "validate production first then sandbox" advice is "simply incorrect" for RC users since "sandbox and production purchases are automatically handled"; sandbox outages cause STORE_PROBLEM rejections, fix = resubmit. RC also: new IAPs "work in Sandbox and TestFlight as long as they're in Ready to Submit status. Apple reviewers can test your IAPs"; first subscription must be submitted together with an app version https://www.revenuecat.com/docs/tools/experiments-v1/creating-offerings-to-test and app-store-rejections page. "RevenueCat automatically detects the environment" https://www.revenuecat.com/docs/test-and-launch/sandbox . => our backend must treat SANDBOX purchases as unlockable during review [INF from above; RC does not literally say "set your backend to unlock sandbox"] . Our webhook must therefore accept SANDBOX env in production webhook config (select "both").
- Sandbox renewal speed [DOC Apple help, no date shown] https://developer.apple.com/help/app-store-connect/test-in-app-purchases/manage-sandbox-apple-account-settings : default "1 month = 5 minutes"; table default row: 1 week 3 min, 1 month 5, 2 months 10, 3 months 15, 6 months 30, 1 year 1 hour. Auto-renews up to 12 times, turns off at the 13th attempt. YES adjustable: ASC > Users and Access > Sandbox > pick tester > "Subscription Renewal Rate" (options every 3 / 5 / 30 min / 1 hour classes), also in iOS Settings > Developer > Sandbox Account.
- Free trial compression in sandbox: Apple page has no trial table; 2-week trial speed [NF]. Guess: trial scaled like a 2-week subscription (~6-ish min) [INF, weak]. (RC web billing sandbox lists trial=5 min but that's RC Billing, not Apple.)
- TestFlight [DOC Apple] https://developer.apple.com/help/app-store-connect/test-a-beta-version/testing-subscriptions-and-in-app-purchases-in-testflight/ : all durations renew every 1 day; 1-month sub renews 6 times then disabled (example). RC says change dated Dec 2024. In TestFlight renewal speed overridable via Sandbox account per Apple note.
