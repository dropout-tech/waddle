# E1：Apple 審查員的「沙盒購買」要怎麼生效——方案比較（2026-10-01）

**狀態：待老闆選方案。選定前不改程式、不套 migration、不部署。**

## 問題一句話
Apple 審查員在審 App 時按「購買 Huddle Pro」，走的是 Apple 的**沙盒（測試）環境**，不會真的扣錢。
我們的收款通知程式（`supabase/functions/revenuecat-webhook/core.mjs` 第 16、48 行）目前**刻意忽略所有沙盒購買**，
購買畫面又設計成「只認伺服器說你是 Pro」（防止有人竄改 App 冒充付費）。
兩者相加 → 審查員買完會一直卡在「同步比平常久」，Pro 永遠不生效 → **幾乎確定被退件**（購買後沒交付內容）。

而且這不是一次性問題：**每次送審新版本**，審查員都可能再買一次，所以方案必須是長期政策。

## 誰拿得到「沙盒購買」？（決定風險大小的關鍵）
- 一般人從 App Store 下載的正式版：購買一律走正式環境，**拿不到沙盒購買**。
- 只有這三種人會產生沙盒購買：我們自己用 Xcode 裝的版本、TestFlight 測試者、Apple 審查員。
- 沙盒收據由 Apple 簽發、RevenueCat 向 Apple 驗證，外人無法偽造。
- 沙盒裡時間被壓縮：一個月的訂閱只撐幾分鐘就續訂／到期（精確數字見「查證」段）。

**建議 C**：審查穩過，又不讓測試資料混進真實付費紀錄；萬一 TestFlight 被拿去濫用可以一鍵關。
注意開關平常要一直開著——關掉的期間如果剛好在送審，會被退件。

**排除 D**：違反 2026-10-01 風險審查定下的原則「Pro 身分只認伺服器」。

## 選 C 之後要做的事（實作時才做，各步驟照規矩先問）
1. 改 `core.mjs`：沙盒事件不再丟掉；分別算出「正式到期日」與「沙盒到期日（最多現在＋24 小時）」。
2. 新 migration：沙盒權益表＋「接受沙盒」開關；`huddle_ops.has_pro` 多看沙盒表（只看未過期且開關開著的）。
   → **套正式庫前問老闆**。
3. 單元測試：沙盒購買生效、24 小時上限、開關關閉時不生效、沙盒不覆蓋正式權益、TRANSFER 事件。
4. 部署通知程式＋設 4 把 secret → **先問老闆**。
5. 用 RevenueCat Test Store 與 Apple 沙盒各實買一次，確認購買畫面從「同步中」變成「Pro 會員中」。

## 查證（2026-10-01，完整筆記與網址見 `2026-10-01-revenuecat-research-notes.md`）
- Apple 官方 TN2413：審查團隊在沙盒環境審 App；伺服器應先驗正式、收到 21007 再驗沙盒
  （https://developer.apple.com/library/archive/technotes/tn2413/_index.html ，舊版 verifyReceipt 時代的文件，
  但「審查走沙盒」這件事至今不變）。→ 我們現在「一律丟掉沙盒」正好違反這條建議。
- Apple：TestFlight 安裝的 App 一律走沙盒；TestFlight 訂閱每 24 小時續一次。
  沙盒帳號預設 1 個月＝5 分鐘、1 年＝1 小時，最多續 12 次，可在 App Store Connect 調速率。
  → 24 小時上限不會影響審查（審查員幾分鐘內就看完）。
- RevenueCat「App Store 退件」說明：RevenueCat 本身會自動處理沙盒與正式；第一個訂閱商品要跟 App 版本一起送審。
  （https://www.revenuecat.com/docs/test-and-launch/app-store-rejections）
- RevenueCat webhook 可選送 production／sandbox／both。選 C 時要設成 both（或建兩組）。
- RevenueCat Test Store 的購買被當成「沙盒資料」；webhook 欄位推測為 `environment=SANDBOX`、`store=TEST_STORE`（官方沒明寫，實測時要看一次）。
  → 現行程式連 Test Store 測試購買也會丟掉，選 A／B／C 任一都能解。
- **地雷**：Test Store 的金鑰（`test_` 開頭）放進 Release 版（含 TestFlight、App Store）會讓 App **故意當機**，
  Capacitor 沒有關掉這個保護的開關。Test Store 只能用在 Xcode 直接跑的 Debug 版；TestFlight 以後一律換正式金鑰（`appl_`）。
