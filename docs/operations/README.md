# Huddle 營運後台與會員推薦

本次實作提供 `/admin` 與 `/membership`。會員選單包含「會員與推薦」，已授權管理員的會員頁會顯示後台入口。這份說明對應本分支程式；完成本機驗證不代表已部署正式站。

## 啟用前

1. 先於隔離環境套用既有 `20260920082633_billing_entitlements.sql`，再套用 `20260925075939_operations_referrals.sql`。後者建立非公開 `huddle_ops` schema、帶驗證的 RPC、帳號停用限制，以及不儲存任務內容的活動統計。
2. 由專案擁有者在受信任的 SQL 管理介面，為已確認的 Huddle 帳號授予後台權限。不要將 service-role key 或管理員 Email allowlist 放進瀏覽器程式。請先確認使用者提供的管理員 Email，不能從測試帳號推定擁有者。
3. 用一般帳號驗證無法呼叫管理操作，再用管理員登入 `/admin`。
4. 在「活動設定」自行開啟新戶體驗、手動贈送、優惠兌換、推薦獎勵及站內提醒。贈送／促銷相關開關預設全關；排行榜總開關預設開，但每位會員預設不公開。
5. 發布前需另行完成 migration、實際管理員授權、站台部署與真實新帳號驗收。本分支未修改正式資料，未開啟扣款。

管理員授權範例（替換已確認的 Email，要求恰好一筆已驗證帳號；只在受信任 SQL 管理介面執行）：

```sql
do $$
declare selected_user uuid;
begin
  select id into strict selected_user from auth.users
  where lower(email) = lower('REPLACE_WITH_CONFIRMED_ADMIN_EMAIL')
    and email_confirmed_at is not null;
  insert into huddle_ops.admins(user_id) values(selected_user)
    on conflict do nothing;
  insert into huddle_ops.audit(actor_id, action, target, detail)
    values(null, 'bootstrap_admin', selected_user::text,
           '{"reason":"owner-approved initial administrator"}');
end $$;
```

一般會員的 `user_metadata` 或前端路由無法授權管理員；每次管理 RPC 都查詢管理員表，撤銷權限不需要等待 JWT 過期。

## 日常操作

- **數據總覽**：會員／近 30 天註冊、DAU／WAU／MAU、付費權益有效、贈送權益有效、推薦與兌換數。日期以台北時區計算。
- **會員**：依化名或 Email 搜尋，每頁 50 筆；查看註冊、最近操作、付費／贈送到期日與推薦來源。贈送或補發須填原因；操作使用識別碼防止重試重複發放。可以撤銷未使用贈送時間，或停用／恢復帳號。
- **優惠碼**：建立與編輯名稱、天數、開始／結束、名額、適用對象、疊加與備註；啟停、複製連結、查看最近 50 筆兌換紀錄。已兌換的時間不會因活動編輯而改變。名額不能縮到低於已使用數。
- **推薦紀錄**：每個新會員只綁定一次，不因登入、重整或回呼重送而重複計數。管理員可撤銷異常推薦，扣除排行計數及雙方相關推薦贈送。即使該次獎勵因年度上限為 0 天，也可撤銷。
- **訂單與訂閱**：目前列出 RevenueCat 同步的權益快照。正式購買仍停用，沒有付款金額／失敗訂單／退款／下次扣款日的完整資料，介面明確標示。不得將贈送時間或快照筆數當作營收／訂單數。
- **操作紀錄**：管理員、對象、操作內容／原因與時間，以及兌換、推薦事件。
- **活動設定**：各活動獨立開關；推薦預設 30 天、朋友體驗總共 30 天、新戶體驗 14 天、推薦年度上限 360 天。上限 0 代表暫不發推薦天數，仍計有效推薦。
- **公告與通知**：產品公告、維護通知，可排程發布、編輯與下架。顯示於已登入工作空間；到期提醒在活動設定控制。這是站內通知，不會寄 Email 或推送 OS 通知。
- **來源分析**：活動優惠碼／會員推薦／自然註冊的註冊數、開始使用、一週留存與目前付費數。

## 會員流程與隱私

1. 開啟「會員與推薦」，一鍵產生固定推薦碼及分享連結。原生 App 分享公開網站網址，不會分享 `capacitor://localhost`。
2. 朋友用連結註冊時自動帶入，也可自行輸入。Email 註冊把碼保存在帳號 metadata 作為待處理輸入，跨裝置驗證後仍可套用；OAuth 同瀏覽器使用限期本機暫存。metadata 不用於權限或直接發獎。
3. 經帳號驗證、註冊後 7 天內，且帳號建立於此功能啟用後，才可成為有效被推薦者。自我推薦、重複領取及被停用帳號不發獎。Email 驗證不是「每個自然人只一帳號」的保證，仍需管理員處理濫用。
4. 優惠碼與推薦碼分別處理；某一碼無效不阻擋另一碼。失敗碼保留供會員頁重試，暫存最長 7 天且綁定來源帳號。
5. 朋友推薦體驗總天數包含已領取的新戶體驗。先成功兌換活動碼時，不再額外領朋友體驗；推薦人仍可獲獎。推薦人獎勵會累積，依台北曆年計上限。
6. 會員自選化名（2–24 字），可以選擇上榜或退出。排行榜只回傳化名、人數、名次、是否為本人，沒有 Email、頭像、帳號 UUID 或私人的任務／筆記。相同人數並列，最多 100 位。儲存化名也更新既有分享功能使用的 profile 名稱。

## 權益與金流界線

贈送採獨立 ledger，保留來源、天數、原因與撤銷紀錄。發放時接在現有權益後面；付費快照更新會把未使用贈送重新排到付費期間後。退款／付費撤銷也會重排，避免多送空白期間。撤銷贈送不扣除已付費權益。

**贈送不會變更 App Store／RevenueCat 的自動續訂扣款日期。** 商店續訂仍需會員在原購買渠道管理；付費持續續訂時，未使用的贈送時間繼續保留在其後。不要向會員承諾「自動延後商店扣款」。

既有產品仍提供免費核心工作空間；本次建立會員權益、贈送與營運操作，未擅自把現有功能加上付費牆。Free／Pro 的功能分界、商店商品與完整結帳仍需另行定義及啟用。

## 指標定義與限制

- 活躍：有經登入者新增／修改任務或排程，統計只存 user ID、日期與來源表名，不存內容；初始資料寫入也可能算一次，不應解讀為深度使用時數。
- 新資料自 migration 啟用後收集，不回填歷史活動。
- 到期體驗會員付費比例：已結束 trial 且目前有付費權益的人數／已結束 trial 人數；不是歷史首次付費轉換率。
- 優惠碼「付費」：兌換後發生過付費快照更新且目前仍有效；不是精確首次成交歸因。
- 來源優先序：已兌換優惠碼 > 有效推薦 > 自然註冊。補碼會改變分類。
- 一週留存：註冊滿 8 天，註冊後第 6–8 個台北日曆日有操作。分母不包含尚未滿天數的會員。
- 目前不提供取消訂閱原因、金額營收、完整功能事件分析或外寄通知，因正式購買／相關事件尚未啟用。
